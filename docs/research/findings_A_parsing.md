## 7. Expression building
Implicit AND (4445-4464): AddOperand inserts AND after operand or `)`; AddNonOperand inserts AND before `!`/`(` after operand or `)` → `ETH! RARE` = ETH AND !RARE.
Shunting-yard (3704-3766): binary op pops every NOT/binary → AND/OR equal precedence left-to-right (`A OR B C` = (A OR B) AND C); NOT pushed w/o popping (binds to next operand/group). STRAY `)` → function returns immediately: processed kept, REST OF RULE DISCARDED (`ETH) AND RARE` = ETH; `A OR B) AND C` = A OR B) (3748-3752). At end, popping stops at first `(` and everything below DISCARDED (3755-3765): `(ETH AND SOCK>0` fine; `ETH OR (SOCK>0 AND RARE` loses the OR → never matches.
Convert (3474-3524): false if operator lacks operands, leftover paren, final stack ≠ 1 → root = -1 → EvaluateTree false (3451-3453, 3526-3528). Rule stays in RuleList, never matches: `OR ETH`, `ETH AND`, `ETH OR OR RARE`, `!` alone.
EMPTY conditions → Rule::Evaluate true (ItemDisplay.h:1152-1160): `[]`, `[()]`, all tokens dropped (`[Eth]`, `[NOT]`, `[STAT9999>0]`), missing `]` → match EVERY item. `[!Eth]` → only NOT → never. `[ilvl>5]` → item code `ilvl` → never.
